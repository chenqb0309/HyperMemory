# HyperMemory：思考放大協定（Amplifier Protocol）

## 定位

Amplifier 是三層認知流的第二層，介於 Flashback（回憶）與 Imprint（刻錄）之間。

```
Flashback → Amplifier → Imprint
    ↑                        |
    └────── 循環回饋 ────────┘
```

它不是獨立的「執行步驟」，而是在每次回憶後、每次刻錄前，**有意識地比對過去與現在的模式**。

## 用途

1. **模式識別**：當前情況與哪個過往經驗相似？哪裡不同？
2. **盲點揭露**：使用者是否正在重複踩同一個坑？
3. **收斂導向**：在刻錄前，確認新結論是否真的「新」，還是既有知識的重新發現

## 觸發時機

Amplifier 不是被排程觸發的，而是被 Flashback 或 Imprint 的結果觸發的：

| 觸發點 | 條件 | 動作 |
|--------|------|------|
| Flashback 回傳了 node | 有匹配記憶 | 比對該記憶與當前情境的異同 |
| Flashback 未命中 | 無匹配記憶 | 判斷是否真的是全新經驗，還是關鍵字沒選對 |
| Imprint 準備寫入 Type 2 | 有 prenode | 順便檢查 prenode 鏈上是否有其他相關 node 可參考 |
| Imprint 準備寫入 Type 3 | 跨 chain | 強制執行跨 cluster 關聯掃描（Step 5b），這本身就是 Amplifier 行為 |

## 執行步驟

### Step 1：取得參考點

從當前對話中提取：
- 使用者的核心問題或目標
- 採取的方案或嘗試
- 結果（成功/失敗/未完成）

### Step 2：載入相關記憶

從 Flashback 結果（或 Imprint 的 prenode 鏈）取得參考記憶：

- 若 Flashback 已命中 → 使用該 node 及其 prenode 鏈
- 若 Flashback 未命中 → 用當前問題的關鍵字做語義近似掃描
- 若 Imprint 有 prenode → 讀取 prenode 鏈上相鄰 node

### Step 3：模式比對

比較當前情況與過往記憶：

| 維度 | 問自己 |
|------|--------|
| 情境相似度 | 問題領域、技術棧、環境是否相同？ |
| 行為模式 | 使用者的做法跟上次失敗時是否一樣？ |
| 結果模式 | 這次的結果跟上次是否類似？ |
| 偏離點 | 哪裡不同？這次做了什麼新的嘗試？ |

### Step 4：輸出洞察

輸出結構化的比對結果：

```
模式比對結果：
  相似點：[列出具體相似處]
  差異點：[列出關鍵差異]
  重複模式：[若發現使用者反覆踩到同一個坑，明確指出]
  建議方向：[基於過往經驗的建議]
```

### Step 5：決定下一步

| 比對結果 | 下一步 |
|----------|--------|
| 完全匹配，無新資訊 | 不需 Imprint，直接回應 |
| 部分匹配，有新資訊 | Imprint Type 2（繼承既有經驗） |
| 跨領域連結浮現 | Imprint Type 3（匯聚多個來源） |
| 全新問題，無相關記憶 | Imprint Type 1 |
| 發現使用者重複錯誤 | 先指出模式，再決定是否 Imprint |

## 與認知協議的對應

認知協議第 2 條（跨時間模式識別）就是 Amplifier 的行為規範。Amplifier 是該規範的結構化執行方式。

## 已知限制

- Amplifier 依賴 LLM 的模式識別能力，不是機械式比對
- 在事實可驗證領域（build/test/debug）精準度高
- 在策略/設計等主觀領域，模式識別可能不夠可靠
- 不強制每次對話都執行——只有當 Flashback 或 Imprint 被觸發時才啟動
